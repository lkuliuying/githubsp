# GitHubSP v0.4.3

发布日期：2026-11-20。更好地识别视频简介、帖子里的 GitHub 地址，说明只有源代码的项目，并修复滚动卡顿。下载核心和数据格式与 v0.4.2 相同。

## 更新内容

### 识别写乱的 GitHub 地址

视频平台和论坛经常过滤外链，作者会把地址写成各种样子。现在剪贴板提示条和输入框都能认出：

- **变形的域名**：`github 点 com/…`、`github[.]com`、`github . com / owner/repo`、`github dot com`、`github。com`，以及全角的 `ｇｉｔｈｕｂ．ｃｏｍ`。
- **论坛跳转链接**：知乎、掘金、CSDN、简书、Gitee 包了一层的外链，会取出里面真正的 GitHub 地址。其他网站网址参数里的地址仍然忽略。
- **加速站链接**：`https://加速站/https://github.com/…` 只取 GitHub 部分，下载照样走 GitHubSP 自己的线路。
- **其他 GitHub 地址**：`raw.githubusercontent.com` 文件地址、源码包地址、`git@github.com:owner/repo.git`、`gh repo clone owner/repo` 都会退回到对应仓库。
- **只写了 owner/repo**：在输入框里直接输入 `owner/repo` 就能读取版本；剪贴板提示条要求前面有「GitHub：」「GitHub 仓库」「GitHub 搜」这类提示，普通句子里的「iOS/Android」不会被误认。
- **粘贴自动整理**：在新建下载、队列顶部的快速下载、我的软件的添加框里粘贴一整段文字，会自动换成识别出的 GitHub 地址；认不出时按原样粘贴。

### 只有源代码的项目

- 仓库一个版本都没发布，或者某个版本没有附件时，不再只提示「换一个仓库」，而是说明这是源代码，通常需要按项目说明自己编译或运行，并提供「用浏览器下载源码 ZIP / 此版本源码」和「打开项目主页 / 版本页面」。源码包由浏览器下载，不进入 GitHubSP 的下载队列。

### 修复

- **滚动一顿一顿**：在附件列表、下载队列等页面用滚轮滚动时，会滚到一半卡住一会儿再一下滑出一大段。原因是窗口线程处理了程序用不到的原始鼠标输入，挡住了网页的滚轮消息，现已关闭。
- **改名或迁移过的仓库读不出版本**：例如输入 `facebook/react`（已迁移到 `react/react`）会报「官方版本页面地址不一致」。现在会先查出仓库当前名称再读取，校验照样严格，标题旁显示「已从 … 改名或迁移」。

## 下载与运行

| 附件 | 用途 |
| --- | --- |
| `GitHubSP-v0.4.3-windows-x64-Setup.exe` | Windows x64 安装版；缺少 WebView2 时下载并安装 Evergreen Runtime。 |
| `GitHubSP-v0.4.3-windows-x64-Portable.zip` | 免安装版；解压完整目录后运行 `GitHubSP.exe`，需要系统已有 WebView2。 |
| `SHA256SUMS.txt` | 校验上述两种分发文件的 SHA-256。 |
| `LICENSE`、`THIRD_PARTY_NOTICES.md`、`FRONTEND-LICENSES.txt`、`RUST-LICENSES.txt` | 项目及第三方许可。 |

请先完全退出旧版（包括托盘图标）再启动新版。v0.4.3 沿用 v0.4.2 的数据目录和数据格式，可以直接覆盖安装，也可以换回 v0.4.2。程序不会自动安装更新，也不会运行下载的文件。

## 验证边界

- 发布前回归：核心、Tauri 宿主和前端测试，以及 Clippy、格式检查和安装包打包。新增测试覆盖各种变形地址、跳转链接、加速站前缀、提示词识别与误判排除、输入框的 owner/repo、源码包地址，以及改名仓库的跟随和校验。
- 用隔离数据在真实桌面程序中核对了 `torvalds/linux`（没有版本）、`facebook/react`（已迁移，版本没有附件）和 `BurntSushi/ripgrep`（正常附件列表）。
- 滚动卡顿在真实鼠标滚动下前后对比：修复前滚轮输入最多被扣住 1～1.8 秒后一次放出 45 格，修复后最多 2 格（正常的逐帧合并）。脚本模拟的滚动不经过系统输入队列，无法复现这个问题，所以靠真实滚动记录确认。
- 已知：滚动或移动鼠标时窗口线程仍有少量 CPU 占用，已不再影响滚动。
- 程序未进行 Windows 代码签名。
