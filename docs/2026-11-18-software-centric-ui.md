# 以「软件」为中心的界面重构（2026-11-18）

侧边栏原有 8 个入口，彼此重叠：下载队列、下载历史、软件文件库都在管下载记录，项目收藏和更新中心都在跟踪新版本，线路检测是低频诊断工具。本轮按 3 个阶段合并页面，侧边栏减到 4 项。试用反馈后首页改回下载队列，见文末「试用反馈后的调整」。

后端只新增一个只读命令 `softwareProjects`，原有 IPC 命令、数据库结构和 Agent/MCP 工具都没有变化。版本号仍为 v0.7.0，尚未发布。

## 导航对照

| 现在 | 合并了 |
| --- | --- |
| **我的软件** | 项目收藏、软件文件库，以及作为页内「更新动态」标签的更新中心 |
| **下载队列**（默认首页） | 下载队列、下载历史（历史变成「已完成」标签） |
| **新建下载** | 原来的仓库附件、附件直链、批量链接三种输入合并成一个输入框 |
| **设置** | 新增「网络」分类，放代理设置和线路检测；「收藏更新」改名「关注更新」 |

## 我的软件

- 每个项目一行，显示本地版本（最近一次下载）、最新版本和本地文件状态。下载过但没关注的项目也会列出。
- 行内主按钮随状态变化：
  - 可更新 →「更新到 vX」
  - 已关注但从没下载 →「下载 vX」
  - 未关注 →「关注更新」
  - 已是最新 → 只显示状态
- 「可更新」的判断：已关注、有最新版本、本地版本标签与最新标签不同，且最新版本没有被忽略。
- 其余操作在「⋯」菜单：查看所有版本、打开所在文件夹、立即检查、标为已读、忽略此版本、项目设置、取消关注。
- 自动选不出附件时（多个候选或降级更新源），会提示是否转到新建下载手动选择。
- 点击某一行，右侧打开详情面板：本地文件（路径、校验、下载时间）、最新版本的更新说明、版本记录和关注设置。
- 原来的「关注规则」和「分组与标签」两个弹窗合并成「项目设置」。
- 已读状态在后端本来就是一套（`ack_watch` 与 `update_disposition` 互相同步）。界面统一用「标为已读」和「忽略此版本」两种说法。

`softwareProjects` 读取最多 5000 条已完成任务，按仓库（不区分大小写）分组，取完成时间最新的一条作为本地版本，只检查这一个文件的存在与大小，不逐个访问历史文件。前端再与快照中的收藏和 `watch_state` 合并，见 `desktop/src/lib/software.ts`。

## 下载队列

- 标签：未完成、进行中、已暂停、失败、已完成，每个标签后显示数量。
- 「已完成」按页读取历史，可在「下载完成」和「已取消」之间切换，并显示文件是否还在原位置。主按钮是「打开文件夹」，文件不在时变为「重新下载」。
- 失败任务在行内显示原因，并提供「重试」按钮。
- 侧边栏角标、页面标题和「未完成」标签统一显示未完成任务数。等待中的任务显示真实名次。后端的 `queuePosition` 是排序序号，不是名次。

## 新建下载与设置

- 输入框会自动识别粘贴的内容：
  - 一个仓库或 Release 页面地址 → 读取版本，回车即可触发。
  - 一个或多个附件链接（每行一个）→ 直接预览确认。
  - 两者混在一起 → 给出提示。
  - 识别规则见 `desktop/src/lib/source.ts`。
- 设置的「网络」分类包含代理和线路检测。线路检测的隐私提示保留：使用加速线路时，加速服务能看到附件地址。
- 设置、关注清单和新建下载中描述实现细节的说明文字，改写为面向用户的说法。

- 核心 138 项、Tauri 宿主 9 项、前端 8 项测试，以及 Clippy、格式检查和生产构建均通过。新增的测试覆盖项目分组、状态判断和输入识别。
- 每个阶段都在隔离数据目录中启动真实桌面程序，使用真实公开 Release，截图核对浅色、深色和 760px 宽度。
- 真机点过「更新到」「关注更新」和线路检测。
- `verify-desktop-ui.cjs`、`verify-software.cjs`、`verify-update-center.cjs` 和 `scripts/lib/desktop-driver.cjs` 已按新导航调整选择器，但这几个完整验收脚本没有重跑。其中后两个需要 Harness 和 MCP 环境。
- 没有在真机上点过已完成列表的「打开文件夹」和「重新下载」。前者会打开资源管理器；后者沿用原历史页的逻辑。

## 试用反馈后的调整（第一批）

试用反馈：平时主要是临时下载某个附件，顺便看看以前下载的软件有没有更新；希望首页是下载队列，页面更紧凑，加速要真正有效。第一批调整如下：

- **首页改回下载队列。** 侧边栏顺序为下载队列、新建下载、我的软件、设置。队列顶部新增快速下载栏：
  - 粘贴附件链接，回车后直接加入队列，保存到最近使用的位置，点击位置标签可以更改。
  - 粘贴仓库地址，会转到新建下载并自动读取版本。
  - 还没有用过任何保存位置时，转到新建下载选择。
- **预览时显示文件大小。**
  - 从版本列表勾选的附件，直接带上列表里的大小（`preview` 新增可选的 `sizes` 参数）。
  - 直接粘贴的链接，并行向第一条线路（GitHub 直连）发送一次 `Range: bytes=0-0` 请求，单个最多等 5 秒，不会把地址发给加速服务。
  - 返回 404/410 的附件标为无效，并提示「GitHub 上找不到这个附件」；其他情况留到下载时确定。
- **Agent 允许目录改为从资源管理器选择**，以列表显示，可以逐项移除。原来手动输入时，路径换行会被拆成两个目录。后端本来就会拒绝不存在或非绝对的目录。
- **「我的软件」新增「全部更新」**：有 2 个及以上可更新项目时显示，依次加入队列，选不出附件的项目汇总在一条提示里。
- 打开「查看所有版本」或从快速下载栏跳转时，新建下载会自动读取版本。

## 第二批：下载提速

试用反馈「无法做到加速下载」。排查发现：
- 原来的「加速」只是在 3 条线路里选一条。
- 小于 16 MB 的文件只用 1 个连接，GitHub 下载服务器又对单个连接限速，所以换线路基本没效果。
- 每条线路测速要在 10 秒内读满 512 KB，网速低于约 50 KB/s 时所有线路都会判成超时，任务停在「等待网络」。

调整如下：

- **多连接分段下载**：
  - 文件达到 2 MiB 就分段，每段至少 1 MiB。段数等于「设置 → 下载 → 同时连接数」，默认 4，可选 1–8，对之后开始的下载生效（`core/src/engine.rs` 的 `plan_parts`）。
  - 恢复点本来就支持任意段数，现在上限从 2 段放宽到 8 段（`files::MAX_PARTS`）。旧任务保持原来的段数继续下载。
  - 每段保存恢复点的间隔随段数加长，避免频繁写盘。
- **自定义镜像**：在「设置 → 网络」添加 HTTPS 前缀（最多 8 个）。重启后作为额外线路参与测速和自动选择，线路标识按地址生成（`mirror:主机/路径`），删除其他镜像不会改变它。重定向白名单包含这些镜像的主机。删除的镜像不再出现在线路列表里。
- **线路下拉框**：新建下载和任务详情里的线路选项，改为从当前线路列表生成，包含自定义镜像。
- **慢速网络测速**：从收到响应头开始最多读约 7 秒；收到至少 16 KB 但读不满 512 KB 时，用已收到的数据估算速度，不再判为超时。
- 代理选项保持「不使用 / 跟随系统 / 自定义」，按用户要求不做自动提示。

实测（同一个 4.5 MB 附件，固定 GitHub 直连，隔离数据）：

| 同时连接数 | 传输耗时 | 平均速度 | 峰值 |
| --- | --- | --- | --- |
| 1 | 65.8 秒 | 67 KB/s | 97 KB/s |
| 4 | 19.2 秒 | 230 KB/s | 602 KB/s |

两次下载的文件逐字节相同，并通过 GitHub 官方 SHA-256 校验。实际提速取决于网络和服务端限制，这只是一次测量。

测试：核心 142 项（新增分段规划、按设置分段、多段暂停续传、慢速测速、镜像校验）。原本验证单连接续传偏移和换线建议的测试，改为显式设置 1 个连接。

## 第三批：紧凑布局

试用反馈「页面空间利用率不够」，按用户选择直接改成紧凑布局，不做密度切换：

- 去掉内容区 1200px 的宽度上限，页面边距从 18/22px 收到 14/18px。设置页保留约 960px 的阅读宽度。
- 下载队列：
  - 概况数字（正在处理、等待中、总速度、限速）移到标题栏；快速下载栏单独一行。
  - 筛选标签、批量操作和搜索合成一行。
  - 任务行从约 88px 降到约 60px：名称和来源一行，进度条和大小一行。窄窗口隐藏来源，详情面板里仍可看到。
- 我的软件：
  - 可更新数和已关注数移到标题栏，自动检查说明和「软件 / 更新动态」标签放在同一行。
  - 列表加一行表头，代替每行重复的「本地 / 最新」标签，行高从约 83px 降到约 45px。
- 新建下载：底部的保存位置和预览按钮紧跟内容，不再被推到窗口底部、中间留出大片空白。
- 1040px 以下隐藏标题栏的概况数字，960px 以下标题栏按钮只显示图标、列表恢复两行布局。截图核对了 1600、1280、760 三种宽度和深色模式，均无横向溢出。

Agent 接入说明暂时搁置。

## 第二轮试用反馈：字号、宽度与分页

第 4 版试用反馈：
- 列表字太小、内容太多，显得拥挤，希望能自己选每页显示几条。
- 设置页空间利用率低、字偏小。
- 配色、动效和动画需要改进。

经与用户确认，分三批处理，这一批先解决第一个问题：

- **字号整体上调一档**：正文 14px，次要文字 13px，角标最小 12px，层级关系不变。
- **内容最宽 1440px，并且靠左对齐**：和标题对齐，超宽窗口不再把每行拉成一长条。上一批完全去掉宽度上限，在约 2000px 宽的窗口里，文件名和按钮相隔太远。
- **分页**：已完成、未完成、我的软件、更新动态的底部可以选每页 10 / 20 / 50 / 100 条，默认 20 条。各列表分别记住选择，只保存在本机。已完成列表的历史查询新增可选的 `pageSize` 参数（5–100，`Store::query_history_sized`），原有每页 20 条的接口和 Agent 工具不变。
- **精简行信息**：完成时间显示为「刚刚 / 5 分钟前 / 3 天前」，鼠标悬停时显示完整时间；「文件存在」这类正常状态不再显示，只在文件缺失时提示。
- **界面缩放**：「设置 → 通用 → 界面缩放」提供 90% / 100% / 110% / 125%，立即生效，只保存在本机。外框和弹窗里的视口单位已按缩放比例换算，110% 时不会出现横向滚动。

### 第二批：设置页

- **布局**：分类改为左侧竖排导航，每项带图标，搜索框放在导航上方；右侧每个分类再分成小组，例如「下载 → 速度 / 附件选择」「网络 → 代理与镜像 / 线路检测」。页面最宽 1280px。960px 以下的窄窗口，分类改为横排并自动换行。
- **字号与控件**：分类标题 22px，设置名称 15px，说明 13.5px；下拉框、输入框和按钮高 38px；开关加宽。
- **即时保存**（用户选择）：
  - 开关和下拉框改完立即保存，按顺序排队提交，每次都基于上一次成功保存的结果；保存失败时恢复原值并提示。
  - 限速和附件名规则这类文本框，在离开输入框或按回车时保存，非法值会被拒绝并恢复。
  - 网络代理和自定义镜像需要重启才生效，所以保留单独的「保存」：有改动时出现提示条，保存后提供「立即重启」。离开页面或关闭窗口时，只有网络设置的未保存改动会提醒。
  - 标题栏显示「正在保存… / 已自动保存」。
- 限速输入框最多显示 3 位小数，避免 KiB/s 换算出现「1.999872」这样的数字。

### 第三批：主题色与动效

参考了这些来源：
- AB Download Manager（多主题、强调色进度条）
- Gopeed（跟随系统主题，8 种强调色）
- Clash Verge Rev（与本项目同为 Tauri + React，用蓝色主色）
- 微软 Fluent 2 的动效令牌：时长 100–500ms，减速曲线 `cubic-bezier(0.1, 0.9, 0.2, 1)`
- Emil Kowalski 的动效文章：进入用先快后慢的曲线，一般不超过 300ms；高频和键盘操作不加动画；动画可打断；减少动态时关闭位移

本批改动：

- **主题色**：可选蓝色（默认）、青绿、紫色、石墨（即原来的黑灰色）。每种主题色在浅色和深色下各有一套变量，覆盖原有的强调色、进度、链接和信息色。深色下主按钮用较浅的底色配深色文字。实测 8 种组合的主按钮文字对比度在 5.2–16.1 之间，均高于 WCAG AA 的 4.5。
- **外观**：浅色 / 深色 / 跟随系统；选「跟随系统」时随 Windows 设置实时切换。标题栏按钮仍可一键切换深浅色。旧版保存的「深色」偏好会自动迁移。外观和主题色只保存在本机（`githubsp.appearance`），在首次渲染前应用，不会先闪一下默认样式。
- **动效令牌**：`--dur-fast` 120ms、`--dur-base` 200ms、`--dur-slow` 280ms，统一用 `--ease-out` 曲线。
  - 按钮、标签、导航、列表行：悬停和按下时颜色平滑过渡，按下时轻微缩小。
  - 页面切换：从 240ms 改为 200ms，带 4px 上浮。
  - 详情面板、通知面板：从右侧滑入。
  - 菜单：从按钮一角缩放展开。
  - 弹窗：轻微上浮并放大；提示条：从下方浮入。
  - 新加入的任务：从上方滑入，并用主题色短暂高亮约 1.6 秒。
  - 进度和速度数字不做动画。开启「减少界面动效」或系统关闭动画时，以上动效全部关闭（沿用原有规则）。

### 试用反馈：消息位置与后台提醒

- **消息提示移到顶部**：标题栏下方居中，从上方浮入；原来在窗口底部，容易漏看。快速下载成功后的提示只显示保存文件夹的名字，完整路径不再撑成两行。
- **后台完成提醒重新设计**（`desktop/src/NoticeApp.tsx`）：
  - 最新一条用大卡片显示：带状态图标（下载完成为绿色、发现新版本为主题色、下载失败为红色），下面是文件名，以及项目、版本、大小和用时。
  - 下载完成时可以直接「打开文件夹」，或者「在 GitHubSP 中查看」。其余提醒显示为简要列表（最多 2 条）。
  - 底部有一条细进度条，表示 8 秒后自动收起；鼠标悬停或键盘操作时暂停，离开后重新计时。减少动态时不显示。
  - 提醒窗口高度跟随内容，固定在屏幕右下角，不跟随主窗口的界面缩放。为此给窗口权限增加了 `core:window:allow-set-size` 和 `core:window:allow-set-position`。
  - 外观和主题色与主窗口一致；在主窗口修改时，提醒窗口通过存储事件同步。
