# 参考 cult-ui 的界面细节升级（2026-11-19）

从 [cult-ui](https://github.com/nolly-studio/cult-ui) 的 150 多个组件里挑了 7 个适合下载工具的交互，分两批试用后合入。cult-ui 面向 Tailwind v4、React 19、motion 和 Base UI，本项目是 Tailwind 3.4、React 18 和手写 CSS，所以只借交互思路，全部用项目自己的 CSS 变量重写，没有新增依赖，也没有沿用它的玻璃、光晕等视觉风格。所有新动效都跟随「减少动态效果」设置。来源与许可见 `desktop/THIRD_PARTY_NOTICES.md`。

## 第一批

| 改动 | 位置 | 参考 |
| --- | --- | --- |
| 选中底色在标签间滑动 | 下载队列状态标签、已完成类型切换、我的软件筛选、「软件 / 更新动态」下划线 | direction-aware-tabs、halo-segmented |
| 进度条改用 scaleX 绘制；大小未知时用渐变滑条；检测线路、等待网络、重试、校验时在已下载部分上扫过光带 | 队列行、任务详情 | halo-progress |
| 复制后图标换成对勾、文字变「已复制」，1.6 秒后复原，按钮宽度不变 | 任务详情的复制链接、保存位置；我的软件的复制路径 | copy-button |

侧边栏原有的弹簧滑块逻辑抽成 `desktop/src/lib/useSpringThumb.ts`，侧边栏和页内标签共用。

## 第二批

| 改动 | 位置 | 参考 |
| --- | --- | --- |
| 拖动把手调整排队顺序，松手立即按新顺序显示；Esc 取消，方向键逐位移动 | 下载队列（不搜索、本页至少两个排队任务时） | sortable-list |
| 顶栏限速变成可点的入口，弹窗里有预设和输入框，应用后显示成功并自动关闭 | 下载队列顶栏 | popover-form |
| 数量变化时数字滚动到新值（速度不滚动） | 侧边栏角标、页面标题计数、顶栏统计、标签计数 | rolling-number |

- 队列列表顺序改为：正在处理 → 排队中（按名次）→ 暂停、失败等其余任务；第一段和第三段按添加时间从新到旧。原来全部按添加时间排序，排队任务夹在中间，没法拖动。
- 拖动用指针事件实现。Tauri 在 Windows 上接管了窗口的文件拖放，HTML5 拖放事件不可靠。
- 后端 `reorder` 命令新增 `direction: "to"` 加 `index`，直接移到等待队列的指定位置；原有 up / down / top 不变。等待队列按排队序号、创建时间、id 排序，与核心调度一致。
- 顶栏限速 1 MB/s 以下显示为 KB/s（十进制，与设置页一致），以上最多三位小数。

## 验证

- 前端测试、Tauri 宿主测试、Clippy、格式检查和生产构建通过。新增测试覆盖拖动到指定位置和顶栏限速写法。
- 两批都在隔离数据目录中启动真实桌面程序，用真实公开 Release 下载，截图核对浅色、深色和 760px 宽度：滑块对齐、进度宽度、复制反馈、拖动让位与提交、后端顺序、Esc 取消、方向键、限速弹窗的预设、校验、成功态与焦点归还、计数滚动。
- 「忙碌光带」是手动加属性看的样式，没有在真实的检测线路状态下专门截图。
- 窗口宽度小于 1040px 时顶栏统计整体隐藏，限速入口也随之隐藏，与原来一致。
