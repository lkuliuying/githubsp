## 1. 摘要

当前产品已经解决“能不能下载”：分段续传、官方 SHA-256 校验、线路探测、数据库兼容与备份都具备。真正的短板集中在三处：

1. **追踪闭环缺失**：能发现新版本，但通知是会话级的、重启即丢；发现后要四步才能下载。
2. **无代理可用性弱**：API 单点直连、无令牌、限流 60 次/小时；直链批量预览还被 API 阻塞。
3. **信任不足**：未签名；已校验的摘要反而在界面上被隐藏。

本计划用三个版本完成转型：

- **v0.3.0 追踪闭环**：未读持久化、更新提醒、一键下载、调度修复、Atom 降级、版本说明。
- **v0.3.1 网络与入口**：系统代理、可选令牌、自定义镜像、直链批量去阻塞、剪贴板与默认目录。
- **v0.4.0 信任与数据**：校验可见、更新流程、便携模式、备份轮换与恢复。
- **v0.4.1 / v0.5.0**：历史与队列增强、日志诊断、文档拆分、国际化与深色模式。
- **M6 发布阶段（最后）**：代码签名。先把能力做齐，再申请证书与签名服务。

关键指标（验收口径见第 10 节）：

- 200 个收藏、API 不可用、应用重启三种情况下，仍能在托盘/提醒窗看到未读，并在两次点击内开始下载。
- API 不可用时，100 条直链批量预览 ≤ 2 秒，任务创建 ≤ 5 秒。
- 开启系统代理后，重定向白名单与 HTTPS-only 约束 100% 保持。
- 校验结果在任务详情可见；代码签名在 M6 发布阶段完成，不阻塞能力版本。
- 现有测试全绿，新增功能的默认值不改变旧行为。

| P-14 | 无日志、无诊断导出 | 全局搜索无日志实现 | 问题反馈只能截图 |

### 2.2 根因

- **通知被当成“事件”，而不是“状态”**：notices 存在内存里，未读无法跨会话表达。
- **API 是单点**：目录、收藏、摘要、自身更新全部依赖 `api.github.com`，且没有降级通道。
- **兼容契约限制了数据设计**：`user_version=2` + 共享 JSON，新字段可能被旧版丢弃。
- **串行传输是刻意设计**：不稳定因素多，不适合为了“并发”破坏确定性。

### 2.3 用户路径上的断点

```text
首次启动 → 找版本 → 选附件 → 下载 → 完成 → 追踪项目 → 发现新版 → 再次下载
   │          │         │        │       │        │           │          │
   │          │         │        │       │        │           │          └─ 需要 4 步
   │          │         │        │       │        │           └─ 托盘无提示
   │          │         │        │       │        └─ 只在应用运行时检查
   │          │         │        │       └─ 只能打开目录
   │          │         │        └─ 无任务栏进度
   │          │         └─ 无平台筛选/自动匹配
   │          └─ 无说明/日期
   └─ 无默认目录、无剪贴板监听
```

## 3. 目标、指标与非目标

### 3.1 产品目标

1. **追踪可依赖**：发现、告知、处理形成闭环，跨重启有效。
2. **无代理可用**：默认场景下下载与追踪都能工作，API 不可用时可降级。
3. **下载可信**：签名、校验可见、更新流程可核对。

### 3.2 量化指标

| 维度 | 指标 | 目标 |
| --- | --- | --- |
| 追踪 | 发现→开始下载 | ≤ 2 次点击 |
| 追踪 | 200 收藏、API 不可用、重启后 | 24 小时内仍有未读提示 |
| 追踪 | 失败重试 | 1 分钟内首次重试，指数退避，上限 1 小时 |
| 网络 | 100 条直链预览（API 不可用） | ≤ 2 秒返回，≤ 5 秒全部创建 |
| 网络 | 代理开启后的白名单 | 100% 拦截站外重定向 |
| 信任 | 发布产物（M6） | 有效 Authenticode 签名 |
| 体验 | 首次下载 | ≤ 3 个动作（粘贴、选目录、创建） |
| 质量 | 现有测试 | 全绿；`clippy` 无新增警告 |
| 兼容 | 旧版数据库 | v0.2.3 / v0.2.5 / v0.2.7 可读写 |

### 3.3 非目标（本计划不做）

- 默认并发下载（保持串行；最多提供高级选项，见 D-06）。
- 自动安装/自动替换正在运行的程序。
- GitLab / Gitea / 私有仓库（令牌仅用于公开仓库配额与网络可达性）。
- 遥测、账号体系、云同步。
- UI 整体重做；保留现有布局与组件。

### 3.4 动效目标（v0.3.0 追加）

1. **反馈一致**：按钮、开关、输入框、进度条、导航与页面切换使用同一套时长与缓动。
2. **不挡路**：动效只做反馈，不延迟数据刷新、不阻塞输入、不改变布局尺寸。
3. **可关闭**：设置项“减少界面动效”或 Windows“显示动画”关闭时，所有过渡立即完成。
4. **原生实现**：使用 Slint 属性动画，不引入 WebView、视频播放器或 Remotion 运行时。

“动效覆盖率”按交互点统计：主要按钮悬停/按下、开关与复选框、输入焦点、进度条、导航下划线/角标、页面切换、提醒窗入场，共 7 类；验收时逐项勾选。

5. **实做现状（2026-10-24）**：7 类交互点已全部接入 `Motion` 令牌，其中“按钮悬停/按下”在 v1.2 基础上追加了图标旋转与点击涟漪，“导航”由“下划线宽度展开”改为单根滑动指示条 + 顶栏滑动药丸。按下缩放经技术验证不可行（Slint 的 `percent` 类型不可 animate），已列入 D11 决策并放弃；依据见 [`docs/tech-stack-survey.md`](tech-stack-survey.md) 第 5.2 节。

## 4. 设计原则与硬约束

1. **兼容优先**：`PRAGMA user_version=2` 不变；新数据放新的设置 key 或新表，不往 `preferences` / `favorites` 的 JSON 里加字段。
2. **默认值等于旧行为**：新增开关默认关闭或“自动”，升级后用户不应感到行为突变。
3. **不自动执行下载文件**：任何“打开/运行”都必须显式点击；自动下载默认关闭。
4. **安全边界不放松**：HTTPS-only、重定向白名单、拒绝凭据/查询参数/目录穿越；代理与镜像属于显式选择，并提示第三方可见 URL。
5. **令牌不进数据库、不进日志**：DPAPI 加密文件存储；备份包默认不含令牌。
6. **串行默认**：并发只作为实验性高级选项，且必须通过独立特性开关。
7. **每个功能可回滚**：新增能力尽量挂在设置项后面；回滚只需关开关或回退版本。
8. **验收先于合并**：每个 PR 必须带测试与验收记录；UI 变更附三种窗口尺寸截图。

## 6. 详细需求

### 6.1 追踪与通知

#### T-01 调度修复

**问题**：失败后 `last_checked` 被写成当前时间，自动循环又要求 6 小时，导致 `next_check` 的 60 秒退避失效。

**行为**：

- 自动循环只判断 `now >= next_check`（缺省为 `last_success + interval`）。
- 成功后：`next_check = now + interval`，清空 `error`。
- 失败后：`next_check = now + min(retry_after, backoff)`；退避 1、2、4、8、16、32、60 分钟，上限 1 小时。
- 手动“检查全部”忽略 `next_check`，但保留每收藏 60 秒去重。
- 禁止把失败时间写进 `last_success`。

**验收**：失败后 60 秒内自动重试；成功后按间隔；重启后 `next_check` 仍有效。

#### T-02 检查间隔

**行为**：新增设置 `watch.interval_ms`，可选 15 分钟、1 小时、6 小时、24 小时，默认 6 小时。

**约束**：当 `收藏数 × 24 / 间隔` 超过当前 API 配额时，设置页给出警告（建议配置令牌或 Atom）。

**验收**：修改后下一轮生效；重启保留；旧版读不到该 key 时回落 6 小时。

#### T-03 进度、取消、并发

**行为**：

- 快照新增 `checking`、`check_total`、`check_done`、`check_current`（仅内存）。
- “检查全部”显示进度与“取消”按钮；取消保留已完成的收藏。
- Watcher 并发上限 3，所有 API 请求仍由 `Catalog` 的全局门串行/限流。

**验收**：200 收藏检查期间可取消；UI 不冻结；取消后不再发请求。

#### T-04 未读状态持久化

**数据**：新增设置 key `watch_state`（JSON），不修改 `Favorite` 结构：

```json
{
  "schema": 1,
  "repositories": {
    "owner/repo": {
      "acked_release_id": 123,
      "notified_release_id": 123,
      "last_downloaded_asset": "Tool-1.2.3-win-x64.exe",
      "published_at": 1712345678000,
      "notes_excerpt": "本次更新修复了……"
    }
  }
}
```

**行为**：

- 未读 = `favorite.latest` 存在且 `id != acked_release_id`。
- “全部已读”/单卡“标为已读”更新 `acked_release_id` 并立即落库。
- 删除收藏时清理对应条目；超过 200 项时随收藏一起裁剪。
- 读取失败（JSON 损坏）时重建空结构并记录日志，不阻塞启动。

**兼容**：旧版只写 `preferences`、`last_directory`，不会碰 `watch_state`；迁移/备份的逐行比较已覆盖 `settings` 全表，无需改结构。

**验收**：重启后未读仍在；旧版打开并写库后新 key 不被删除。

#### T-05 提醒呈现

**方案 A（v0.3.0，推荐）**：复用 `completion.rs` 的独立置顶窗口机制，新增“更新提醒窗”：

- 主窗在后臺时出现，显示“3 个项目有新版本”，点击进入收藏页并定位；
- 不自动消失，需“查看/忽略”；
- 同一批检查合并为一条；
- 失败不影响检查结果。

**方案 B（v0.3.x 增强）**：自绘 `Shell_NotifyIcon` 托盘，支持气泡、tooltip 更新、角标；或托盘 tooltip 显示“N 个新版本”。

**方案 C（后续）**：Toast + AUMID。需要开始菜单快捷方式，免安装场景不稳定，暂不作为首选。

**验收**：主窗隐藏、检查发现新版时 8 秒内出现提醒；点击两次内进入下载确认；不重复弹同一条。

#### T-06 提醒内容与操作

**行为**：提醒与收藏卡展示：仓库、版本号、发布时间、说明首行（截断 120 字）、未读标记。

操作：`查看说明`（应用内 Markdown）、`下载最新版`（预选附件并进入确认页）、`标为已读`、`忽略本次`。

#### T-07 Atom 降级

**行为**：

- 新增 `ReleaseProvider` 抽象；API 失败或配额耗尽时，改用 `https://github.com/{owner}/{repo}/releases.atom`。
- 解析 `entry` 的 `id`、`updated`、`title`、`link`，取最新条目；支持 ETag/If-None-Match 与 60 秒缓存。
- Atom 不提供 `prerelease` 标记：标记为“未确认正式版”；API 恢复后校正。
- Atom 仅用于“发现”，不提供附件摘要；下载仍走原有链路。
- 失败静默降级，不影响 API 路径；解析异常记录日志。

**依赖**：`quick-xml`（或等价轻量解析库），需更新许可证清单。

**验收**：屏蔽 `api.github.com` 后仍能发现新版本；API 恢复后自动回到 API。

#### T-08 关注规则

**数据**：`watch_state.repositories[repo].rule`：

```json
{ "include_prerelease": false, "asset_pattern": "*win*x64*.exe", "auto_download": false }
```

**行为**：

- `include_prerelease`：允许把预发布纳入发现。
- `asset_pattern`：简单通配符（`*`、`?`），仅匹配文件名；多命中时取最新上传且唯一的，否则跳过并提醒。
- `auto_download`：发现新版后自动创建任务；默认关闭；不自动运行；仍走串行队列。
- 规则变更立即生效；非法通配符拒绝保存。

**安全**：自动下载只在“用户显式开启 + 规则匹配唯一”时执行；通知里说明将下载的文件名与大小。

#### T-09 收藏卡增强

**行为**：

- 卡片显示：未读徽标、最新版本、发布时间、说明摘要、上次检查（相对时间）。
- 主按钮从“查看版本与附件”扩展为“下载最新版”（按上次附件名/规则匹配）+“查看版本与附件”。
- 更多菜单：标为已读、编辑规则、复制仓库链接、取消收藏。
- “有新版本”筛选 chip；统计卡增加“有更新 N”。

**验收**：从卡片到确认页 ≤ 2 次点击；无匹配附件时给出明确提示与手动入口。

#### T-10 收藏导入/导出

**行为**：导出 JSON（收藏 + 规则 + 未读状态，不含令牌）；导入校验仓库格式、去重、上限 200；失败不部分写入。

### 6.3 网络

#### N-01 系统代理

**行为**：

- 设置项三态：自动（读取 WinINET/环境变量）、手动（URL）、关闭。
- 自动模式读取 `WinHttpGetIEProxyConfigForCurrentUser`；PAC 暂不支持，检测到则提示并回退直连。
- 手动模式校验 `http/https/socks5`，拒绝凭据出现在 URL；代理仅用于出站连接，不改变重定向白名单。
- 首次启用提示：“代理运营方可以看到你访问的 GitHub 地址”。

**验收**：本地测试代理可下载、可浏览；关闭代理立即恢复直连；白名单测试通过。

#### N-02 可选 PAT

**行为**：

- 设置页输入令牌，保存到 `%LOCALAPPDATA%\com.githubsp.desktop\credentials.dpapi`（DPAPI 当前用户）。
- 验证按钮调用 `/rate_limit`，显示配额与重置时间；不显示令牌明文。
- 所有 API 请求带 `Authorization: Bearer`；绝不写入数据库、备份包、日志。
- 清除令牌立即生效；迁移数据目录时复制凭据文件，失败则要求重新输入。

**验收**：配置后配额显示 5000；抓包/日志无令牌；清除后回落 60。

#### N-03 自定义镜像

**行为**：

- 设置页维护镜像列表：名称、前缀 URL、启用、排序；内置三条可禁用但不可删除。
- 校验：HTTPS、无凭据、无查询/片段；允许路径前缀。
- 路由 ID 与显示名分离；修改名称不影响任务记录。
- 重定向白名单从常量改为“内置 + 已启用镜像的 host”运行时集合。
- 探测、下载、低速换线全部纳入自定义线路；诊断页显示自定义线路。

**安全**：镜像终止 TLS，能看到文件内容；首次启用提示。禁止 `http://` 与私网地址（除非显式高级开关）。

**验收**：新增镜像后可在诊断页看到并选中；删除/禁用后不再请求；白名单不包含未启用域名。

#### N-04 直链批量去阻塞

**问题**：`intake::preview` 对每个附件直链调用 `catalog.resolve`，最坏 15 秒/条。

**行为**：

- 附件直链在预览阶段只做本地解析与去重，不请求 API；大小显示“未知”。
- 任务创建后，下载引擎获取元数据（现有 10 秒超时）并回填大小；UI 自动刷新。
- 需要空间预检时，已知大小按已有值累计，未知项按现有“无法完整估算”规则提示。
- 仓库/版本链接仍走 API（这是产品语义），但错误提示区分“接口不可用”和“链接无效”。

**验收**：API 不可用时 100 条预览 ≤ 2 秒、创建 ≤ 5 秒；有 API 时行为与现状一致。

#### N-05 配额可见与限流聚合

**行为**：

- `Catalog` 记录 `x-ratelimit-remaining/limit/reset`，快照暴露 `api_status`。
- 设置页/底部显示“API 42/60 · 15:20 重置”；未配置令牌时提供“配置令牌”入口。
- 限流时只显示一条全局提示；收藏检查跳过剩余项并标记“等待配额”，不逐卡报错。
- 手动“检查全部”在限流时直接提示剩余等待时间。

#### N-06 错误可操作化

**行为**：错误消息旁提供“复制错误”“复制直链”“打开设置”“重试”；全局错误条支持复制。错误文案包含下一步动作，而不是只描述现象。

#### N-07 接口不可用引导

**行为**：检测到 `api.github.com` 连续失败时，显示横幅：“GitHub 接口不可用，可直接粘贴附件直链下载；或在设置中配置代理/令牌”。按钮：打开设置、查看帮助。横幅可关闭，同会话不重复。

## 7. 数据与兼容设计

### 7.1 存储位置

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 现有任务/历史/收藏/设置 | `tasks.sqlite3` | 不变；`user_version=2` |
| 新增设置 | `settings` 表新 key | `watch`、`network`、`ui`、`recent` |
| 未读与规则 | `settings` 表 `watch_state` | JSON，按仓库索引 |
| 令牌 | `credentials.dpapi` | DPAPI，当前用户 |
| 便携模式 | `exe目录\data\` | 含数据库、位置配置、备份、日志 |
| 日志 | 数据目录 `logs/` | 轮换 |

**为什么用 settings 新 key，而不是新表/改 JSON**：

- 旧版只写 `preferences`、`last_directory`，不会覆盖未知 key；
- 现有迁移的逐行比较覆盖 `settings` 全表，新 key 自动被校验和复制；
- 不改 schema，不需要新增迁移分支。

### 7.2 内存模型变更

`Snapshot` 增加（不持久化）：`api_status`、`checking`、`check_progress`、`unread_favorites`、`update_available`。

`Release` 增加：`published_at`。`ApiRelease` 增加 `published_at`。

`Favorite` 保持不变；富信息放 `watch_state`。

### 7.3 兼容矩阵

| 场景 | 要求 |
| --- | --- |
| v0.2.3 / v0.2.5 / v0.2.7 打开新库 | 可正常读写；新 key 保留 |
| 新版打开旧库 | 自动补默认值，不丢历史 |
| 迁移数据目录 | 新 key、凭据、日志、备份全部复制并校验 |
| 回退旧版 | 不崩溃；新功能退回默认（无未读/无代理） |
| 备份恢复 | 恢复后 `user_version` 不变，旧版可读 |

### 7.4 默认值

| 设置 | 默认 | 理由 |
| --- | --- | --- |
| 代理 | 自动 | 有代理用户可用；失败回退直连 |
| 令牌 | 空 | 不强制账号 |
| 检查间隔 | 6 小时 | 与现状一致 |
| 自动下载 | 关 | 安全 |
| 启动自动继续 | 关 | 避免意外流量 |
| 剪贴板监听 | 关 | 隐私 |
| 日志 | 开 | 支持效率 |
| 便携模式 | 不启用 | 需显式标记 |

## 8. 架构改动

```text
当前：Library(60s 定时循环) ──→ Catalog(API) ──→ Manager ──→ Engine

目标：Watcher（调度/规则/进度/取消）
        ├─ Provider: ApiProvider → AtomProvider（降级）
        ├─ Notifier: 提醒窗 / 托盘 / 未读状态
        └─ Catalog（限流/缓存/配额状态）
              └─ Manager ──→ Engine（串行）
```

- **Watcher**：独立服务，持取消令牌；通过 `Manager` 读写，不直接操作数据库；对外暴露进度与取消。
- **ReleaseProvider**：`fetch_latest(repo) -> ReleaseSummary`；API 与 Atom 两个实现；失败链式降级。
- **RouteRegistry**：内置 + 自定义；生成 reqwest 路由；重定向白名单动态派生；诊断复用。
- **MetadataResolver**：懒加载、并发 8、超时 3 秒；供批量预览/任务创建后补全。
- **Notifier**：`notify(repo, release)`；未读状态由 `watch_state` 派生；提醒窗复用 `completion.rs` 的窗口创建/定位逻辑。
- **UI**：`state.slint` 增加属性；收藏页卡片动作；设置页新增“网络”“追踪”模块；错误组件支持复制。

**不动的东西**：Manager 单 actor 写入、Engine 串行调度、Store 兼容层、单实例与迁移阶段机。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 旧版丢弃新 JSON 字段 | 用户切回旧版后设置丢失 | 新数据放独立 key/表；文档说明；测试覆盖 |
| 提醒窗被全屏程序遮挡 | 用户错过更新 | 同时更新托盘 tooltip/角标；后续评估 Toast |
| Toast/AUMID 在免安装场景不稳定 | 通知不可用 | 先用独立提醒窗，不押注 Toast |
| 代理破坏安全边界 | 重定向/HTTPS 约束失效 | 代理只影响出站连接；白名单独立测试；代码评审 |
| 自定义镜像 SSRF/钓鱼 | 用户下载到错误内容 | HTTPS、拒绝私网、首次提示、保留官方摘要校验 |
| Atom 格式/限流变化 | 降级失效 | 只解析必要字段；失败静默；超时与缓存 |
| 令牌泄露 | 账号风险 | DPAPI、只读用途、不进日志/备份、可随时清除 |
| 签名采购周期长 | 拖慢正式版发布 | 签名后置到 M6，能力版本不等待；未签名构建明确标注 |
| i18n 改造范围失控 | 拖慢主线 | 只包主流程字符串；布局不动；分阶段 |
| 兼容测试成本高 | 发布延期 | 复用 v0.2.5 的 fixture 与兼容测试；每里程碑跑一次 |
